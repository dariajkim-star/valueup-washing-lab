## 이 국면의 정체 — 만든 규칙과 없앤 규칙

v2에서 도입한 규칙과 **철회·은퇴시킨 규칙**을 세어보면 거의 일대일이다.

| 없앤 것 | 왜 |
|---|---|
| `washing_flag` (지표 전체) | 실측 True=**0건** — 켜질 수 없는 경고등 |
| `washing_only` 토글 | 위 지표에 걸려 **항상 빈 결과**를 내던 죽은 필터 |
| `is_cover_notice` 참조 문구 검사 | `count==4`에서 변별력 **0** (26/26이 표준 서식) |
| `OPAQUE_MIN_RANK` 고정 상수 | 모집단 20개에서 고정 임계는 자의적 |
| "소각 이행" 라벨 | 데이터에 없는 인과를 주장 (16 중 5만 계획 기간 내) |

| 만든 것 | 무엇을 대체 |
|---|---|
| `opacity_rank` | `washing_flag`의 자리 — 고의 판정 대신 공시 격차 |
| `is_unrankable` | 참조 문구 검사 — 규칙을 넓히지 않고 없애는 쪽 |
| `min/max_opacity_rank` 필터 | 죽은 토글 |
| 채점 축별 하한 | 적자연도 음수가 타 축 이행을 상쇄하던 결함 |
| 임계 화면 다이얼 | 고정 상수 |

**우리가 만든 것의 절반은 우리가 만든 것을 지우는 데 쓰였다.** 이것이 낭비가 아니라 이 프로젝트가 실제로 한 일이다 — v1은 "재는 도구"를 지었고, v2는 **"그 자가 제대로 재는지"를 실데이터로 검사했다.**

## 잘된 것

1. **실측이 여섯 번 판을 뒤집었고, 여섯 번 다 이겼다.** 방의 법("실측 숫자가 토론을 이긴다")이 실제로 집행됐다:
   - `washing_flag` True=0 → 지표 은퇴
   - 점수순 상위 7칸이 전부 단일 이진축 100점, 세 약속 다 지킨 기아가 8등 → 기본 정렬 전환
   - 참조 검사가 26/26 동일 서식 → 규칙 폐기
   - 불투명순 1·2·3등(삼성화재·LG화학·하나금융)이 전부 오탐 → `is_unrankable`, 모집단 23→20
   - all-null의 정체가 파서 버그가 아닌 **첨부 사각지대** → 백로그 P1-3
   - `retired` 16 중 계획 기간 내는 5 → 라벨 정정, 백로그 P1-4

   각 건마다 **선행 가설이 있었고 전부 틀렸다.** 틀린 게 사람이 아니라 데이터한테 틀린 것이라 매번 30분 안에 방향이 바뀌었다.

2. **해법이 매번 "규칙 추가"가 아니라 "규칙 제거"였다.** 레아의 문장("규칙을 넓힐 게 아니라 없애야 합니다")이 세 번 연속 옳았다 — 참조 검사 폐기, 죽은 토글 교체, 고정 임계 해제. **규칙이 복잡해질 때가 규칙이 틀렸을 때다**가 이 방의 작동 원리로 정착했다.

3. **두 달 묵은 미결 두 건이 같은 날 닫혔다.** 정렬 정책은 "커버리지 축 신설"이 아니라 **이미 반대편에서 재고 있던 `opacity_rank`를 동행 노출**하는 것으로("우리는 이미 갖고 있었다"), 임계 소유권은 화면 다이얼로. 둘 다 **새 개념을 만들지 않고** 닫혔다.

4. **"측정 불가"와 "가장 나쁨"을 끝까지 분리했다.** `is_unrankable`(본문 4축 전무 → 순위에서 제외)과 오늘의 소각 배지 판단(계획 기간 미상 7종목을 "안 했다"로 밀지 않음)은 같은 원칙의 두 적용이다. 모집단이 23→20으로, 판단 가능 범위가 **좁아지는 방향**의 결정을 두 번 다 선택했다.

5. **배선 실증이 DoD로 정착했다(Epic 3 회고 액션아이템 #4의 결실).** Epic 6의 화면 작업 전건이 네트워크 로그·라이브 조작으로 검증됐다 — 무필터 32 / `min_opacity_rank=0.7` 5 / `=0.25` 12 / 해제 32. "보이지만 죽어있는 컨트롤"이 v2에서 한 건도 나오지 않았다.

## 어려웠던 것

1. **파티가 스토리 절차를 우회했고, 그 청구서가 문서로 돌아왔다.** Epic 6은 `create-story` 없이 진행됐다. 빠른 대신 흔적이 안 남았고 — **`sprint-status.yaml`이 2주간 "전 에픽 done, 마감 국면"이라고 거짓을 말했다.** 문서가 낡은 게 아니라 반대를 말한 상태였다. 회고 3건 미실시(이 문서로 해소)도 같은 뿌리다.
   → **속도로 받은 것을 기록으로 지불하지 않으면 문서가 거짓말한다.**

2. **설계는 가정한 분포로 하고, 실제 분포는 매번 극단이었다.** True=**0**건, 26/**26** 동일 서식, **전건** `market_fallback`, `retired` 16종목 **전부** 2024Q4. 이 프로젝트의 실데이터는 "적당히 흩어진" 적이 한 번도 없다. 그런데도 설계 단계에서 매번 정상 분포를 가정했다.
   → **규칙을 코드로 옮기기 전에 그 규칙이 실제로 무엇을 가르는지 먼저 세어야 한다.** 여섯 번 다 세어본 뒤에야 알았다.

3. **v1의 마감 근거 하나가 사후에 무너졌다.** "execution_score 커버리지 개선 vs 정직성 프레임" 결정(07-14)의 근거에 "`washing_flag` 19종목 작동"이 있었으나, 07-23 실측에서 True=0으로 드러났다. 결정 자체는 유효하지만 **근거 한 줄은 틀렸다** — `sprint-status`에 정정 주석을 달았다.
   → 마감 시점의 "작동한다"는 판단도 실측 없이는 믿을 수 없다.

4. **`market_fallback` 전건 문제를 아무도 건드리지 않았다.** KSIC sector가 sparse해 peer 버킷(min=5)이 서지 않고, 결과적으로 "업종 내 비교"가 전부 전체시장 비교다. 유니버스 33종목이라는 구조적 원인이 있어 확대 전엔 안 풀리지만, **화면은 여전히 "업종 내"라고 말할 수 있는 상태**다. 3주째 열린 채로 남았다.

5. **개별 회고 3건 미실시.** Epic 4·5는 리뷰 번들(review-bundle-4-2, -5)이 부분적으로 회고 역할을 했으나 형식적 회고는 없었다. Epic 6은 파티 원장이 대신했다. 이 통합 문서가 사후 보정이지만, **에픽 종료 시점의 온도는 이미 식은 뒤**라 잃어버린 관찰이 있다.

## 핵심 교훈

- **규칙을 만들면 그 규칙이 실제로 무엇을 가르는지 세어라 — 코드로 옮기기 전에.** v2의 여섯 번의 반전이 전부 이 순서를 거꾸로 밟아서 생겼다. `washing_flag`는 2주, 참조 검사는 하루, "소각 이행" 라벨은 두 시간 만에 뒤집혔다. **세는 비용은 항상 되돌리는 비용보다 쌌다.**
- **규칙이 복잡해질 때가 규칙이 틀렸을 때다.** 예외 조항을 붙이고 싶어지면 규칙을 넓히지 말고 **없앨 수 있는지** 먼저 물어라. v2에서 이 질문이 세 번 나왔고 세 번 다 없애는 쪽이 옳았다.
- **"측정 불가"는 "가장 나쁨"이 아니다.** 이 구분을 지키면 모집단이 줄고 화면이 초라해진다. 그래도 지켜야 한다 — 넓은 척도가 거짓말하는 척도였다. 판단 가능 범위를 좁히는 결정을 v2에서 두 번 선택했고 둘 다 옳았다.
- **사실을 지우지 말고, 사실에 붙인 문장을 고쳐라.** 소각 배지 처리가 이 원칙의 최종형이다. 배지를 떼는 것(사실 삭제)도, 계획 기간으로 게이팅하는 것(미상을 "안 함"으로 밀기)도 아닌 **라벨 정정**이 답이었다.
- **속도로 받은 것은 기록으로 지불해야 한다.** 파티가 스토리 절차를 건너뛴 대가가 2주치 거짓 문서와 회고 3건 부채로 돌아왔다. 파티 주도 개발을 계속하려면 **파티 원장이 스토리 파일 역할을 하도록 형식을 정해야** 한다.
